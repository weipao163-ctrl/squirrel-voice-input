# 0.1.46 更新后输入法菜单缺项：恢复与安装器修订

日期：2026-11-17。环境：macOS 27.0（26A428），Apple Silicon。主程序和语音助手均为0.1.46，尚未发布 GitHub。

## 现场结论

用户报告菜单栏仅剩“ABC、简体拼音”。故障时增强版仍存在于系统设置的已添加列表，TIS 返回已启用、可选择且当前已选中；主程序和助手仍运行，微信输入会话仍有实际 Rime 活动。现场安全输入为关闭，LaunchServices 只有受保护的系统安装路径。这与此前 Chrome 密码框未释放安全输入导致变灰的故障不同。

原安装器仅在当前登录用户身份下调用 `TISRegisterInputSource`，缺少系统级登记。这一安装缺口已确认并修复；本次菜单缺项的唯一触发原因尚未通过单变量实验确定。

## 恢复步骤与因果边界

1. 仅正常刷新 macOS 的输入法菜单进程；用户确认仍然缺项。输入法、语音助手及个人设置未变。
2. 通过原生 TIS API 刷新增强版启用状态。随后在系统设置中，仅移除增强版并重新添加同一项，点击“完成”。其他输入源保留。
3. 通过管理员授权，以 root 执行已经安装、签名有效的主程序的 `--register-input-source` 维护入口。命令退出码为0，两个系统输入源缓存均实际更新。
4. 用户最终确认：“增强版已出现，可以选择”。

设置界面重新添加与系统级登记都发生在最终确认前，不能将其中某一步单独说成已证实的唯一恢复原因。原生登记列表在重新添加前后的父项/子项顺序相同，因此没有把列表顺序当作根因。

旧缓存本来就包含增强版标识和正确的系统路径。因此，本机证据只能证明原用户级登记没有刷新这两个系统文件、root 登记使其更新，不能证明旧缓存完全缺失该输入法或某个具体字段错误。

同系统版本的另一输入法维护者曾用沙盒进程验证用户级登记与系统级缓存之间的差异，并采用 root 调用 TIS 登记；见[维护者记录](https://github.com/scholay/rimes/blob/main/docs/macos/input-source-cache-recovery.md)。这是调查依据，不能代替本机对菜单缺项的独立复现。本轮没有删除任何应用或系统缓存。

## 安装器防复发修订

- `pkg-system-install.sh` 在事务登记钩子中，先执行系统级登记，再执行登录用户登记，最后才以登录用户身份启用和启动输入法。
- 相同版本重装也刷新两个范围；任何范围失败均进入原有文件回滚并尝试恢复旧系统程序的登记。移除事务完成后的重复登记。
- 提权入口仅接受固定系统目标，检查整个程序树属于 root、非符号链接目标且无组/其他用户可写文件，并验证严格签名。退役的用户目录程序仅以原用户身份登记。
- 个人输入源选择、词库、设置与钥匙串仍由原用户管理。未新增后台定时重新添加或强制重启机制。

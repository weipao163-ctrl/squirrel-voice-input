# 用户选词在重新启动或后续使用后恢复旧排序

日期：2026-11-11。版本：0.1.44。以下区分真实用户数据副本、合成回归与本机安装结果。

## 根因与证据

现场方案为 `rime_ice`，运行库为 librime 1.17.0。用户词库存在，LevelDB 的启动恢复和压缩记录正常，未发现损坏或写盘失败。只在隔离副本导出用户所举的两个词，记录为“京畅”33 次、“经常”25 次。

使用现用运行库与原选词脚本，在副本内选“经常”6 次，其累计记录变为31次。独立进程重新打开后仍保留记录并以“经常”为首选；继续提交1,500次其他拼音后，“京畅”又回到首选，重新打开进程后也是如此。这复现了用户描述的现象，同时排除了本次样本中“学习只存在内存”的解释。

Rime 原生学习每次增加累计次数，同时给予会衰减的近期权重。历史累计33次的词仍高于新选择累计31次的词；近期优势消退后，旧排序恢复。重新启动并不必然立即重置词频；本次明确复现的是后续使用导致的排序回退。

实现依据为 [librime UserDictionary](https://github.com/rime/librime/blob/1.17.0/src/rime/dict/user_dictionary.cc)、[Memory 提交路径](https://github.com/rime/librime/blob/1.17.0/src/rime/gear/memory.cc)及 [ScriptTranslator 累计学习](https://github.com/rime/librime/blob/1.17.0/src/rime/gear/script_translator.cc)。

## 修复行为

共享的 `letter_selection.lua` 在原生提交完成后，对已上屏且由用户主动改选的非首选原生词条，比较同一完整编码的累计次数。补充权重为 `min(1000, max(0, 其他词最大累计次数 + 4 - 已选词累计次数))`。首选照常使用原生学习；没有按词或按拼音写死结果，也不降低、删除竞争词记录。

写入仍走 Rime 的原用户词库，不增加另一份私有偏好数据库。先提交原生待写事务，再查询已提交计数并写入强化结果；临时 Memory 在原生提交监听器之后建立，读取当前 tick，随后断开，避免长期持有旧 tick 或重复监听。显式改选立即提交，因此该次词频不再留在原生短暂的待提交/撤销窗口中。

仅处理同一语言、完整原生 Phrase；跳过合成 Sentence、补全猜测、原始字母、外语字母词、自定义字面候选。候选预览或取消没有提交，因此不强化。尊重 `incognito_mode`、`disable_user_dict`、主翻译器禁用词库和禁用字母选词；方案可用 `letter_selection/durable_learning: false` 关闭强化，也支持运行时 `durable_learning_disabled` 选项。原生引擎对这些选项的其他学习行为保持自身规则。

这不是永久钉住首选：以后主动选另一个同音词，仍可改变排序。极大历史差距受每次1000的上限保护，可能需要多次主动改选。自行修改或未知版本的脚本不会被升级器覆盖；两种已知旧版本分别备份，旧备份冲突或符号链接均拒绝覆盖。

## 验证

- 真实个人词库副本：复现旧脚本的31次对33次及1,500次其他输入后的排序回退；新脚本在相同副本上强化后，重新打开、继续输入和再次重新打开均保留“经常”首选。
- `tests/run_learning_persistence.py`：合成词库，34个独立进程检查；字母选择、原生鼠标 API、不调用 finalize 的进程退出、后续1,500次其他输入、改选回原词、取消及三个禁用选项均通过。夹具只含公开合成词，不读取个人数据目录。
- 原有 `tests/run_real_rime.py`：22项真实 Rime 检查通过，涵盖分段句子、字母/鼠标、翻页、数字原文、重载和原生学习。
- 原有 `tests/test_letter_selection.py`：53项通过。
- 实际生产脚本升级器：10项文件夹具通过，包括旧版升级、幂等、保留自定义、冲突/符号链接和历史备份保护；7项系统安装事务检查通过。

个人副本与完整词库导出均留在忽略的本地证据目录，不纳入公开源码或安装包。最初副本来自运行中数据库，只用于可重复诊断；未将它称为静止状态的原子备份，也不会回写覆盖现场词库。

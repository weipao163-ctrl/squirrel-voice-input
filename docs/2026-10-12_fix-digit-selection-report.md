# 0.1.25：字母选词中数字误提交修复

日期：2026-10-12。适用于启用了两阶段字母选词的方案。源码与安装包发布于 [v0.1.25](https://github.com/weipao163-ctrl/squirrel-voice-input/releases/tag/v0.1.25)。

## 行为

| 操作 | 修复后的结果 |
|---|---|
| 隐藏候选时输入 0–9 | 插入原始数字，不提交中文候选 |
| 空格展开候选后输入 0–9 | 返回原文输入，插入数字，不选择候选 |
| 输入 `lovewin2k`，按回车 | 恰好提交 `lovewin2k` |
| 混合字符串后按空格 | 提交原文及分隔空格 |
| 已选择中文前缀，再输入数字与字母 | 保留明确选择的中文前缀，后续部分按原文输入 |
| 删除全部数字 | 恢复普通拼音编辑；可再次按空格进入字母选词 |
| 关闭字母增强 | 恢复方案原有数字选词行为 |

本版根据使用反馈，将原先兼作选词序号的数字键改为普通数字输入。字母和鼠标仍通过 Rime 的正常候选选择及学习通路工作。

## Evidence → Finding → Path

修复前在真实 librime 1.17.0 的独立固定词库中运行相同回归，28 项里 26 项失败；既覆盖已展开候选，也覆盖隐藏候选和混合字符串。

根因有两处：`lua/letter_selection.lua` 明确将 1–9 转成候选索引；未进入 Selecting 的数字返回 NOOP，又被下游原生 selector／editor 处理，导致候选先提交、数字随后插入。上游数字选择规则可查阅[固定版本的 selector 源码](https://github.com/rime/librime/blob/33e78140250125871856cdc5b42ddc6a5fcd3cd4/src/rime/gear/selector.cc)。

修复让数字在原生 selector 之前通过 Context 的实际输入接口写入组合；包含数字的普通字母串进入临时原文编辑，后续字母、数字、光标移动、删除和确认均恰好处理一次。原文显示接入 `SquirrelInputController.swift`，候选隐藏也由同一状态驱动，不只更换显示标签。特殊触发、修饰快捷键、ASCII 模式与关闭功能继续交给原方案；数字按住重复不使用选词键的重复抑制。

已复制到 Rime 用户目录的旧 Lua 也需要升级。`EnhancementPatch.upgradeBundledLua` 只替换 SHA-256 精确匹配的上一版自有脚本，先写恢复备份，保留自定义脚本和冲突现场。启动入口在引擎创建前执行，GUI 部署使用同一实现。

## 可复现检查

在按构建文档准备好依赖的源码副本运行：

```bash
python3 tools/run_digit_input_regression.py
python3 tools/run_native_letter_probe.py --library "$HOME/Library/Input Methods/SquirrelEnhancedDev.app/Contents/Frameworks/librime.1.dylib"
python3 tools/run_macos_core.py
```

真实引擎专项覆盖两种候选状态的全部数字、混合字符串、数字小键盘、重复输入、光标中间插入、退格、取消、分隔空格、已选择中文分段以及关闭功能后的原数字选词。可通过 `--local-rime` 对个人方案源文件做只读复制，在全新目录部署与验证，学习数据库不复制。

本次构建为 Apple Silicon、macOS 13+ 的本地证书签名版本，保留原证书身份，不具备 Apple Developer ID 公证。首次安装的系统手动允许方式见安装说明。

实际检查汇总在本报告末尾；离线引擎、共享 Core、安装包及升级文件事务不等于所有软件中的物理键盘真机验收。本次不采音、不访问 API Key、不调用云识别。

# 0.1.28：首次输入候选窗定位与源码复查

修复宿主暂未返回光标坐标时，拼音候选窗出现在屏幕角落的问题。此问题影响窗口显示位置；文字仍通过当前 IMK 客户端提交，所以可以出现“候选窗位置错、文字上屏位置正确”的现象。用户反馈包括单屏 WPS 表格搜索框，本次修复作用于所有输入框共用的路径，不增加应用名单。

## 范围与边界

以 v0.1.27 的 220 个受版本控制文件为基线，盘点 Swift、Lua、原生桥接、构建/安装脚本、测试和公开资源。对输入事件、候选布局、语音目标、采音生命周期、云端协议、进程通信、设置/密钥与文件写入边界做源码追踪，配合全部 Python AST、shell 语法检查和下列回归。没有读取用户 Keychain、录音或提交云识别任务；测试使用公开词库和隔离目录。

这是源代码复查和受控组件验证，不是形式化验证，也不是全部第三方依赖的逐行安全审计。当前环境未运行 Semgrep/CodeQL；不能将本次未发现其他可确认安全漏洞解释为“没有任何潜在漏洞”。WPS 搜索框中的真人连续输入仍待使用者复验。

## 已确认问题与修复

| Finding | Evidence | 位置与根因 | 修复 |
| --- | --- | --- | --- |
| F-1，界面功能，中等 | E-1、E-2 | `SquirrelInputController.showPanel` 在 `KeyboardInputPosition.caret` 返回空时使用 `.zero`，并且不主动重试 | 不把零坐标当作光标。当前请求最多查询 8 次，重试间隔合计约 1 秒；有效坐标返回后自动显示，不需要再按键 |
| F-2，界面功能，中等 | E-1、E-2 | 所有控制器共享一个候选窗，旧控制器迟到的失活通知无条件隐藏新会话窗口 | 只有拥有窗口的控制器可隐藏它；激活、提交、失活、销毁会话及新内容更新都会撤销旧定位请求 |
| F-3，界面功能，低 | E-3、E-2 | 中英文模式提示走“无候选”快速分支，可能用上一次输入框或零坐标 | 待显示模式提示也走当前客户端的异步定位；纯隐藏候选仍保持零几何查询 |
| F-4，布局功能，低 | E-4、E-5 | `SquirrelPanel.show` 的布尔条件缺少分组，竖排靠边时绕过 `memorize_size=false` | 关闭记忆尺寸时允许窗口正常缩小；开启时保留原行为 |
| F-5，布局功能，低 | E-5、源码条件 | 竖排锚点用全局 Y 除以屏幕高度，忽略屏幕原点 | 改为与当前屏幕中线比较；正/负原点平移夹具验证。没有宣称实测外接显示器 |

F-1 至 F-4 的旧路径均有失败对照。定位工作继续在按键回调结束后执行，不增加每键同步等待。每次查询前后均重新验证请求号、输入代次、当前客户端和活动控制器，防止宿主查询期间重入切换焦点。重试只读取几何信息，不调用 `insertText` 或 `setMarkedText`，不改变组合、选词或语音目标的安全验证。

若宿主一直不提供有效坐标，本次重试停止并保持候选窗隐藏；后续输入会重新尝试。此行为避免窗口落到虚构的位置，但不承诺修复宿主永久缺失几何信息的问题。

```bash
python3 tools/run_native_keyboard_input.py --label candidate-position
python3 tools/run_native_candidate_panel.py
python3 tools/run_native_voice_target.py
```

## 其他检查

- 159 项 Swift Core、53 项 Lua/文件、22 项真实 Rime、原生补丁配方、31 项数字专项和 9 项安装文件事务通过。
- 105 项原生语音目标检查、24 项合成 PCM 转换/排空检查、12 项真实签名 IPC 通信，以及各 11 项 IPC 配置/启动检查通过。没有真人麦克风或云端测试。
- 核查了 IPC 的证书/标识/UID/PID 绑定、消息和队列上限；网络端点固定、拒绝重定向、协议大小/文本/状态检查；Keychain 引用与迟到回调代次；补丁事务和安装回滚边界。本轮未确认新的密钥泄漏、越权上屏或任意路径写入漏洞。
- 60 个 Python/shell 文件通过语法检查。一次音频工具运行误用了本机另一个 SDK，随后显式使用构建 SDK 重跑通过；该工具会重建共享模块，必须串行完成后再跑 IPC。没有将失败运行记为成功。
- 隐藏候选仍为零次宿主几何查询；47 项夹具继续覆盖 100 个新会话、24,000 次按下/松开事件及 500 次重新激活。没有用本地小词库夹具宣称真实 WPS 的固定延迟。

# 0.1.26：首次输入漏出英文与键盘响应优化

## 结果与范围

本版修复新输入会话尚未就绪时，开头字母直接落成英文、后续才进入拼音的通用路由。修复位于所有应用共用的输入控制器，不增加网站、应用或控件名单。

用户在网页的用户名、手机号或邮箱框以及其他输入框遇到过此现象。没有捕获用户那一次真实故障的现场跟踪；以下是生产输入控制器、真实 Rime 与隔离客户端中复现并修复同样现象的证据，不能替代每个网页的实机复验。

## 证据、发现与修复路径

| 证据 | 发现 | 修复路径 |
| --- | --- | --- |
| 旧控制器在真实 Rime 服务暂未就绪时，让 `ni` 直接进入应用，恢复后只处理 `hao` | `create_session` 失败时立即返回“不处理”，没有保留开头输入 | `SquirrelInputController.swift`：首键前准备方案、按控制器暂存并显示未提交输入，恢复后按原事件顺序重放 |
| 隐藏候选时，五个按键仍查询五次宿主光标 | 没有可显示内容也进行同步宿主调用；首键还可能进入语音权限查询 | `showPanel`：隐藏时不查询；可见候选排到按键回调结束后，合并刷新并复核请求有效性；语音权限只在真实触发键上查询 |
| 每个新窗口首次输入都会重新载入同一方案的两套外观 | 重复的配置、字体与布局准备挤在首次输入上 | `SquirrelApplicationDelegate.swift`：复用当前方案与外观，部署、方案或外观变化时重新加载；内部选词通知不再排队刷新 UI |
| Rime 的 `get_property` 使用有界复制，值填满缓冲时可能没有结束符 | 固定 256 字节后调用无界 C 字符串转换，长原文预览可能截断或越界 | 属性读取按需增长、限制到 64 KiB 并有界解码；新增 603 字符原文显示及一次提交检查 |

上游依据：[librime 1.17.0 会话服务](https://github.com/rime/librime/blob/1.17.0/src/rime/service.cc)、[同版本 C API](https://github.com/rime/librime/blob/1.17.0/src/rime_api_impl.h)。本轮使用当前机器已有的真实 librime，不改其核心或个人词库。

## 初始化期间的行为

- 首个按键之前应用当前方案、字母开关、简繁模式和内联显示设置。
- 引擎暂不可用时，普通可打印输入保留在该控制器的内存中，并作为未提交文本显示；恢复后重放原按键，而非把前缀永久插为英文。
- 退格编辑暂存前缀；Esc 取消。焦点失活时原文只提交给原客户端，释放暂存。输入源改变会终止重放。
- 系统快捷键、导航、Space 和 Enter 保留其原语义；不延迟重放发送或命令。暂存最多 128 个事件、等待最多 5 秒；异常持续时明确提示并保留原文，不无限吞键。
- 明确启用的 ASCII 模式和设置表单继续原样输入；安全输入期间不启动或重放初始化暂存。
- 可见候选的延后更新在提交、失活、激活其他控制器或宿主调用重入失活后作废，避免重新弹出旧候选。

## 验证

入口：先按 [构建说明](BUILDING.md) 构建，再运行：

```bash
python3 tools/run_native_keyboard_input.py
python3 tools/run_macos_core.py --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
python3 tools/run_digit_input_regression.py
python3 tools/run_native_ipc_trust.py
```

原生键盘检查编译实际输入控制器、候选窗口和 Rime 调用，仅用本地客户端与不启动语音的传输夹具。覆盖首键、服务未就绪、前缀恢复、退格、Esc、切客户端、ASCII、设置表单、过期候选刷新、宿主重入、长原文，以及连续 100 个新控制器。不是复制一份路由算法来验证自己。

在每次光标查询人为等待 40 毫秒的同一夹具中，旧版五个隐藏候选按键耗时约 207 毫秒，修复后约 0.5 毫秒，查询次数由 5 降为 0。可见候选的光标查询移出了键盘回调。这是受控慢宿主测试，**不表示真实网页、全部应用或整机打字速度提高同样倍数**。CLT 发布前端同时开启 Swift `-O` 优化；Core/Helper 的测试与编译路径保持已有配置。

本轮 159 项 Core、53 项 Lua/文件、22 项完整 Rime、83 项字母 worker、12 项认证 IPC 与配置检查通过。数字专项固定方案 31 项通过；只读个人方案快照的另 31 项也通过，但该隔离快照未完整部署全部辅助词典，不作为个人方案所有附属功能的验收。

安装包仍为 Apple Silicon、macOS 13+ 的本地证书签名版；未做 Apple Developer ID 公证。包内默认方案在空白数据中逐一验证，不依赖本机个人词库。本轮不采音、不访问 API Key、不调用云识别。物理键盘与真实网页登录框的偶发现象需要按实际使用情况继续复核，不能用组件测试声明全应用通过。

## 升级后复验

选择增强版中文输入源，进入新打开的普通输入框，连续输入 `nihao`。开头应保持在同一段拼音组合中；按空格后选择候选。可重复新建窗口、重新聚焦、切换应用，并测试 `lovewin2k`、退格和取消。测试密码框时沿用系统的安全输入行为。

安装、系统放行、数据目录和回滚见 [安装说明](INSTALLATION.md)。升级保留设置和个人词库，API Key 继续留在本机钥匙串；源码与公开安装包不含这些数据。
